# FP2級 学習トレーナー

6分野・各50問、合計300問を収録した、FP2級学科対策の静的Webアプリです。計算・事例問題72問を含み、43の小単元で演習できます。HTML・CSS・JavaScriptだけで動作し、利用時に有料サービス、APIキー、外部フレームワーク、バックエンドは必要ありません。GitHub PagesでHTTPS公開すると、iPhoneのSafariからホーム画面へ追加できます。

問題データ版は`2026-10-11.audit-300`です。300問の問題文・正解・全4選択肢・解説を照合し、292問の本文・選択肢・解説を修正・校正しました。確認済み294問を出題し、根拠不足の6問は「要確認」としてすべての出題から除外します。法令基準日は2026年4月1日、照合日は2026年10月11日です。初期12問を含む既存ID、履歴の保存形式と保存キーを維持し、成績・復習待ちを引き継ぎます。

金融庁、国税庁、日本年金機構、日本FP協会、法務省、国土交通省、裁判所等を優先し、保険・市場理論は業界団体等の一次資料も利用しました。日本FP協会の公表問題の表現を参照して、年額・月額・税引前受取総額・保険期間・保険料払込期間を区別しています。問題ごとの全選択肢の判定・解説・修正理由・出典URLは[AUDIT.md](./AUDIT.md)、機械可読記録は[AUDIT.json](./AUDIT.json)です。アプリの「データ・設定」でも確認件数と要確認理由を表示し、記録を保存できます。

## できること

- 全分野ランダム演習、1つまたは複数の分野別演習、小単元別演習。
- 10・20・60問を指定。不足時は利用可能数を示し、「全○問で演習をはじめる」で全問を出題。
- 問題と選択肢をシャッフル。セッション内に重複はなく、確定後の変更や二重記録を防止。
- 正解の理由と、全4選択肢それぞれの解説、参照資料・法令基準日。
- 間違い直し。復習モードで別セッションにわたり2回連続正解すると克服。再び間違えると復習待ちに戻る。
- 累計・分野別・小単元別・問題別・直近演習の正答率と、独立した学習進捗率。
- 60問・120分の模試を標準選択。12問・24分のお試し模試も利用可能。終了まで正誤を表示せず、終了後に全問の解説を確認。離席・再読み込み中も時間は進む。
- 演習・模試の「解答用メモ」。iPhone等の小さい画面では問題を上、メモを下に分割し、PCでは左右に表示。各窓を独立してスクロールでき、問題の切替え・演習終了・別モード開始でも内容を保持。同じタブの再読み込みでも復元します。
- localStorageによる履歴・途中の演習の保存。再読み込み後にホームの「続きから再開」で再開。
- JSONバックアップ・検証付き復元、削除確認画面、破損データの保護。
- レスポンシブ表示、キーボード操作、iPhoneのセーフエリア対応。
- Service Workerによるオフラインキャッシュと、更新通知。

メモは学習履歴とは別に、そのタブのsessionStorageに保持します。メモを閉じても消えません。別のタブ・端末とは共有せず、JSON履歴バックアップには含みません。保存領域が使えない場合もページを開いている間は保持しますが、再読み込みでは消えます。画面にはメモの説明文を表示しません。メモを開くだけではキーボードを起動せず、入力欄をタップすると入力できます。閉じると通常の全画面表示に戻ります。

## Windowsで起動する

### PythonのローカルHTTPサーバー

1. Python 3が入っていなければ、[Python公式サイト](https://www.python.org/downloads/windows/)から導入します。Node.jsはアプリの利用には不要です。
2. エクスプローラーでこの`fp2-quiz`フォルダを開きます。
3. アドレス欄に`powershell`と入力してEnterを押すと、このフォルダでPowerShellが開きます。
4. 次のコマンドを実行します。

```powershell
py -3 -m http.server 8765 --bind 127.0.0.1
```

5. PCのEdge・Chromeなどで [http://localhost:8765/](http://localhost:8765/) を開きます。
6. 終了するときは、PowerShellで`Ctrl+C`を押します。

`py`が見つからず`python`が利用可能な場合は、次を使います。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

ポートが使用中なら`8765`を`8768`などに変更し、ブラウザのURLも同じ番号にします。ポートやホスト名が変わると別の保存場所となるため、履歴の移行にはバックアップを使ってください。

今回の検証環境ではCodex同梱のPythonを使用しました。通常のPythonが起動できない場合、このPCでは次でも起動できます。

```powershell
& 'C:\Users\ichih\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m http.server 8765 --bind 127.0.0.1
```

`index.html`をダブルクリックした`file://`起動では、外部JSON・JavaScriptモジュール・Service Workerを正常に利用できません。必ずHTTPサーバーかHTTPS公開URLを使用してください。ここで使うHTTPサーバーは静的ファイルを配るためだけの開発用で、バックエンドの実装ではありません。

### VS Codeで開発する

1. VS Codeの「ファイル → フォルダーを開く」で`fp2-quiz`を選択。
2. 「ターミナル → 新しいターミナル」で上記のPythonコマンドを実行。
3. HTML・CSS・JS・JSONをUTF-8で編集し、ブラウザを再読み込み。
4. Service Workerが前のファイルを保持するため、変更時は`sw.js`の`CACHE_VERSION`を更新。アプリに通知が出たら、演習終了後に「更新する」を押す。
5. Node.js 22以上が利用できる場合、次のコマンドで依存パッケージをインストールせずにテストできます。

```powershell
node --test tests/core.test.js tests/pwa.test.js tests/expansion.test.js tests/memo.test.js
```

本環境では`node`は利用でき、`npm`はPATHにありませんでした。`npm install`や`npm test`を使う必要はありません。

## GitHubにアップロードしてPagesで公開する

以下はユーザーが実施する手順です。この作業ではリポジトリ作成・push・公開は行っていません。

1. GitHubにサインインし、「New repository」で`fp2-quiz`などのリポジトリを作成。GitHub FreeでPagesを無料利用する場合は`Public`（公開リポジトリ）を選びます。
2. リポジトリの「Add file → Upload files」を選択。
3. このフォルダ**の中身**をドラッグしてアップロードします。リポジトリ直下に`index.html`が置かれ、`icons/`と`tests/`の階層が保たれるようにしてください。ZIPだけをアップロードしても起動できません。
4. 「Commit changes」で保存。
5. 「Settings → Pages → Build and deployment」で「Deploy from a branch」を選択。
6. Branchを`main`、フォルダを`/ (root)`にして「Save」。
7. 公開完了後に表示される`https://ユーザー名.github.io/fp2-quiz/`を開きます。
8. ホーム・演習・「オフライン利用の準備完了」を確認します。

アプリの内部参照は`./`から始まる相対パスです。Pagesのリポジトリ名や、さらに深いサブディレクトリが変わっても動作する構成です。`manifest`の起動URLとService Workerのスコープも相対です。

公開設定の参照：[GitHub公式ドキュメント](https://docs.github.com/ja/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## iPhoneで利用する

1. 公開したHTTPSのURLをiPhoneのSafariで開く。
2. Safariの共有メニューを開き、「ホーム画面に追加」を選ぶ。表示されない場合は共有メニュー内をスクロールする。
3. 「ウェブアプリとして開く」が表示される場合はオンにし、名前を確認して「追加」。ホーム画面のFP2アイコンから起動する。
4. 最初はオンラインで開き、上部の「オフライン利用の準備完了」を確認する。
5. ホーム画面から起動した状態で数問解き、閉じて再起動し、履歴を確認する。
6. 機内モードにして、再度起動・演習・成績の記録を確認する。

PCの`localhost`はiPhoneからアクセスできません。HTTPSのGitHub Pagesを使ってください。Safariのタブとホーム画面アプリの履歴共有はiOSのバージョンや保存領域の扱いに依存するため、利用する側で確認してください。履歴が分かれる場合はJSONバックアップを移します。

操作の参照：[Apple公式ガイド](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)。共有メニューに追加項目がない場合は「アクションを編集」から追加できます。

## 学習データのバックアップ

- 「データ・設定 → JSONを書き出す」でファイルを保存します。
- iPhoneではダウンロード先の「ファイル」アプリ等から取り出してください。
- 他の端末で「JSONを読み込む」を押し、保存したファイルを選びます。
- 検証後に件数と置き換えの確認画面が出ます。承認すると現在の履歴を**置き換え**ます。履歴の合算・自動同期はありません。
- 進行中の演習はバックアップに含みません。通常演習の確定回答は累計へ反映済みですが、模試の回答は終了して採点するまで累計に含みません。
- ファイルが不正、非対応バージョン、件数に矛盾などがある場合は復元しません。保存に失敗した場合も置き換えません。
- 履歴削除には別の確認画面があります。削除前にバックアップを保存してください。

## 問題を追加・更新する

`questions.json`の`questions`配列に、既存問題と同じ構造のオブジェクトを追加します。JavaScriptへの問題の埋め込みはありません。

```json
{
  "id": "life-051",
  "fieldId": "life",
  "unitId": "life-pension",
  "prompt": "ここにオリジナルの問題文を記載",
  "choices": [
    { "id": "a", "text": "選択肢A", "explanation": "この選択肢が正しい／誤りである理由" },
    { "id": "b", "text": "選択肢B", "explanation": "この選択肢の理由" },
    { "id": "c", "text": "選択肢C", "explanation": "この選択肢の理由" },
    { "id": "d", "text": "選択肢D", "explanation": "この選択肢の理由" }
  ],
  "correctChoiceId": "b",
  "correctReason": "正解の理由と背景・考え方",
  "difficulty": "標準",
  "sources": [{ "title": "実際に確認した公式資料の名称", "url": "https://実際の参照URL" }],
  "basisDate": "2026-04-01",
  "lastVerified": "2026-10-11",
  "needsReview": true
}
```

これは形式の説明用です。架空の参照URLを持つ例のまま学習用問題にしないでください。信頼できる参照先を確認し、単一正解・誤答理由・基準日を整えてから`needsReview`を`false`にします。`true`の問題は全モードで出題から除外されます。

- 問題IDは全体で一意の固定値。表示順や番号として使わず、既存IDを別問題に流用しない。
- 選択肢IDは問題内で一意の4件。正解はIDで指定し、表示のA〜Dとは独立させる。
- 新しい小単元は`fields`内の該当分野の`units`配列に追加。小単元IDは6分野全体で一意にする。
- 分野・小単元は[日本FP協会の公式試験範囲](https://www.jafp.or.jp/exam/subjects_02/)に合わせる。
- 難易度は`基礎`・`標準`・`応用`。日付は`YYYY-MM-DD`。
- `schemaVersion`は構造を変えない限り1。`dataVersion`は更新ごとに変更する。
- **JSONを変更したら必ず`sw.js`の`CACHE_VERSION`も変更する。** キャッシュに収める追加ファイルがあれば`FILES`へ相対パスで追加する。
- ブラウザの履歴を削除せず更新する。問題の追加・並び替えでは、既存IDの学習履歴を保持する。
- 開始済み演習は通常は開始時の問題スナップショットを使う。ただし照合版への更新で問題文・選択肢・正解・解説が修正された問題や要確認の問題を含む場合は、その途中の演習の再開を中止して案内する。既存の確定済み累計成績は保持する。模試の未採点回答は累計に加算しない。

300問を超える拡張も、検証済みの問題を同じJSONに追加して対応できます。履歴は問題IDで維持し、問題数・集計・抽出はデータから計算します。現在の模試抽出は全分野からのランダムで、本番と同じ分野配分を保証する仕様ではありません。

## 設計判断と制約

- アプリ表示とDOMに依存しない学習ロジックを2ファイルに分離。コアはNode.js標準のテストランナーで検証できます。
- localStorageに履歴と進行中セッションを1キーで保存し、確定済み回答と履歴がずれることを防ぎます。模試は終了時に一括採点し、採点後に進行中セッションを消します。
- 同じオリジンで複数のタブから記録が更新されたら、後から気づいたタブの書き込みを停止し再読み込みを案内します。同時操作を前提としたデータベースのロックではないため、学習は1タブで行ってください。
- 保存に失敗した通常演習はメモリ上で続けられますが、警告を表示しバックアップを案内します。復元と削除は、端末への保存成功後だけ画面上の履歴も置き換えます。
- 不正な累計履歴は上書きせず元データをダウンロードできます。途中の演習だけが破損した場合は、正常な累計履歴を保持して再開を中止します。
- 問題の削除で集計対象から外れても、該当IDの履歴はバックアップ・内部保存に残します。同じIDの問題を戻せば成績へ再び反映されます。
- 全体・分野・小単元の累計正答率は、現在の問題集の正解回数÷回答回数です。学習進捗は、現在の問題集のうち1回以上回答した問題数÷全問題数です。要確認の問題も進捗の分母に含むため、別途出題対象外と案内します。
- 未回答を不正解履歴に加算しません。模試結果では出題数を分母にしたスコアと、回答数を分母にした正答率を両方表示します。
- 演習結果は直近50セッションを保持（画面は10件）、問題ごとの累計件数は保持します。終了直後の全問解説はメモリにあり、再読み込み後は直近演習の集計だけが成績画面に残ります。途中の演習は再開できます。
- オフライン用に一式を同じ版でプリキャッシュ。更新版は待機し、通知から演習終了後に有効化します。ブラウザの空き容量等によりキャッシュやlocalStorageが消去されることがあるので、定期的にバックアップしてください。
- 本番の出題範囲・難易度をすべて網羅する問題数ではありません。各問題の参照資料と基準日は`SOURCES.md`および解説に記載しています。
- iPhone実機とGitHub Pages本番での確認は未実施。PC上のブラウザ検証と自動テストの範囲は`TEST-RESULTS.md`を参照してください。

## 更新が反映されない場合

1. オンラインで一度アプリを開く。Service Workerはアプリを開いたとき等に更新を確認します。
2. 新しい版の通知が出たら、進行中の演習を終了し「更新する」を押す。
3. `CACHE_VERSION`の更新とアップロード漏れを確認する。
4. 開発中だけ旧キャッシュを外したい場合は、先に履歴をバックアップし、ブラウザの開発者ツールでService Workerの登録解除・Cache Storageのキャッシュ削除を行う。localStorageやサイトデータ全体を消すと履歴も消えるため注意。

詳細な検証手順と確認済み／未検証の区別は [TEST-RESULTS.md](./TEST-RESULTS.md) にあります。
